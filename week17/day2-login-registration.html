🔐 Registration System Deep Dive

Registration Flow:

  1. User visits /register page
  2. User fills out registration form
  3. Form data is validated
  4. Password is hashed
  5. User record is created in database
  6. User is automatically logged in
  7. User is redirected to dashboard

RegisteredUserController (app/Http/Controllers/Auth/RegisteredUserController.php):

namespace App\Http\Controllers\Auth; use App\Http\Controllers\Controller; use App\Models\User; use Illuminate\Auth\Events\Registered; use Illuminate\Http\Request; use Illuminate\Support\Facades\Auth; use Illuminate\Support\Facades\Hash; use Illuminate\Validation\Rules; class RegisteredUserController extends Controller { // Show registration form public function create() { return view('auth.register'); } // Handle registration public function store(Request $request) { // Validate input $request->validate([ 'name' => ['required', 'string', 'max:255'], 'email' => ['required', 'string', 'email', 'max:255', 'unique:users'], 'password' => ['required', 'confirmed', Rules\Password::defaults()], ]); // Create user $user = User::create([ 'name' => $request->name, 'email' => $request->email, 'password' => Hash::make($request->password), ]); // Fire registered event event(new Registered($user)); // Log in the user Auth::login($user); // Redirect to dashboard return redirect(RouteServiceProvider::HOME); } }

🔓 Login System Deep Dive

Login Flow:

  1. User visits /login page
  2. User enters email and password
  3. Credentials are validated
  4. Password hash is compared
  5. Session is created
  6. User is redirected to dashboard

AuthenticatedSessionController (Login Logic):

namespace App\Http\Controllers\Auth; use App\Http\Controllers\Controller; use App\Http\Requests\Auth\LoginRequest; use Illuminate\Http\Request; use Illuminate\Support\Facades\Auth; class AuthenticatedSessionController extends Controller { // Show login form public function create() { return view('auth.login'); } // Handle login attempt public function store(LoginRequest $request) { // Authenticate user $request->authenticate(); // Regenerate session (security) $request->session()->regenerate(); // Redirect to intended page or dashboard return redirect()->intended(RouteServiceProvider::HOME); } // Handle logout public function destroy(Request $request) { // Logout user Auth::guard('web')->logout(); // Invalidate session $request->session()->invalidate(); // Regenerate CSRF token $request->session()->regenerateToken(); // Redirect to home return redirect('/'); } }

🔄 "Remember Me" Functionality

"Remember Me" allows users to stay logged in even after closing the browser. Laravel creates a persistent login token.

How It Works:

  1. User checks "Remember Me" checkbox
  2. Laravel creates a remember_token
  3. Token is stored in users table
  4. Token is saved as a cookie in browser
  5. On next visit, Laravel validates token
  6. User is automatically logged in

Implementation (Already in Breeze):

<!-- Login form checkbox --> <div class="block mt-4"> <label for="remember_me"> <input id="remember_me" type="checkbox" name="remember"> <span>Remember me</span> </label> </div> // Controller handles remember automatically if (Auth::attempt($credentials, $remember)) { // User is logged in with remember token }

🔑 Password Reset System

Password Reset Flow:

  1. User clicks "Forgot Password?"
  2. User enters email address
  3. Laravel generates reset token
  4. Email with reset link is sent
  5. User clicks link in email
  6. User enters new password
  7. Password is updated

Routes for Password Reset:

use App\Http\Controllers\Auth\PasswordResetLinkController; use App\Http\Controllers\Auth\NewPasswordController; // Request reset link Route::get('/forgot-password', [PasswordResetLinkController::class, 'create']) ->name('password.request'); Route::post('/forgot-password', [PasswordResetLinkController::class, 'store']) ->name('password.email'); // Reset password Route::get('/reset-password/{token}', [NewPasswordController::class, 'create']) ->name('password.reset'); Route::post('/reset-password', [NewPasswordController::class, 'store']) ->name('password.store');

Password Reset Controller Logic:

// Send reset link public function store(Request $request) { $request->validate(['email' => 'required|email']); // Send reset link via email $status = Password::sendResetLink( $request->only('email') ); return $status === Password::RESET_LINK_SENT ? back()->with('status', __($status)) : back()->withErrors(['email' => __($status)]); }
💡 Tip: For password reset emails to work, you need to configure SMTP settings in .env file.

Email Configuration (.env):

MAIL_MAILER=smtp MAIL_HOST=smtp.gmail.com MAIL_PORT=587 MAIL_USERNAME=your-email@gmail.com MAIL_PASSWORD=your-app-password MAIL_ENCRYPTION=tls MAIL_FROM_ADDRESS=your-email@gmail.com MAIL_FROM_NAME="${APP_NAME}"

For Gmail: You need to enable "Less secure app access" or generate an "App Password" from Google Account settings.

✅ Form Validation Rules

Common Validation Rules for Authentication:

Rule Description Example
required Field must have a value 'name' => 'required'
email Must be valid email format 'email' => 'required|email'
unique:table Value must be unique in table 'email' => 'unique:users'
confirmed Must match _confirmation field 'password' => 'confirmed'
min:length Minimum length 'password' => 'min:8'
max:length Maximum length 'name' => 'max:255'

Custom Password Validation:

use Illuminate\Validation\Rules\Password; // Require 8+ characters Password::min(8) // Require letters Password::min(8)->letters() // Require mixed case Password::min(8)->mixedCase() // Require numbers Password::min(8)->numbers() // Require symbols Password::min(8)->symbols() // Check against common passwords Password::min(8)->uncompromised() // Combine multiple rules Password::min(8) ->letters() ->mixedCase() ->numbers() ->symbols() ->uncompromised()
