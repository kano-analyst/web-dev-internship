🌳 Understanding Branches

What is a Branch?

A branch is an independent line of development. It allows you to work on features without affecting the main codebase.

Why Use Branches?

  • Isolation: Develop features independently
  • Experimentation: Try new ideas without risk
  • Collaboration: Multiple team members work simultaneously
  • Organization: Keep different versions separate
  • Code Review: Review changes before merging to main

Branch Visualization

main:     A---B---C---F---G
               \       /
feature:        D---E

Commits D and E happen on feature branch, then merged back to main

🔧 Essential Git Branch Commands

Command Description
git branch List all local branches
git branch branch-name Create a new branch
git checkout branch-name Switch to a branch
git checkout -b branch-name Create and switch to a new branch
git merge branch-name Merge branch into current branch
git branch -d branch-name Delete a branch (safe)
git branch -D branch-name Force delete a branch
git branch -a List all branches (local and remote)

📝 Creating and Using Branches

Step 1: Check Current Branch

# See which branch you're on git branch # Output shows all branches, current branch has * * main

Step 2: Create a New Branch

# Method 1: Create branch git branch feature-form-styling # Then switch to it git checkout feature-form-styling # Method 2: Create and switch in one command (recommended) git checkout -b feature-form-styling

Step 3: Work on Your Branch

# Make changes to files # Then add and commit as usual git add . git commit -m "Add beautiful form styling with transitions" # Make more commits git add . git commit -m "Add hover effects to buttons"

Step 4: Push Branch to GitHub

# First time pushing a new branch git push -u origin feature-form-styling # After that, just use git push

Step 5: Switch Between Branches

# Go back to main git checkout main # Go to feature branch git checkout feature-form-styling # Or use newer syntax (Git 2.23+) git switch main git switch feature-form-styling

🔀 Merging Branches

Merging combines changes from one branch into another.

Fast-Forward Merge

Occurs when there are no new commits on the target branch.

Before merge:
main:     A---B
               \
feature:        C---D

After merge:
main:     A---B---C---D
# Switch to main branch git checkout main # Merge feature branch git merge feature-form-styling # Output: # Fast-forward # styled-form.css | 150 +++++++++++++++++ # 1 file changed, 150 insertions(+)

Three-Way Merge

Occurs when both branches have new commits.

Before merge:
main:     A---B---E
               \
feature:        C---D

After merge:
main:     A---B---E---M
               \   /
feature:        C-D
# Switch to main git checkout main # Merge creates a merge commit git merge feature-form-styling # Git opens editor for merge commit message # Save and close to complete merge

Delete Branch After Merge

# Delete local branch git branch -d feature-form-styling # Delete remote branch git push origin --delete feature-form-styling

⚠️ Merge Conflicts

Merge conflicts happen when the same line in a file is changed differently in two branches.

When Conflicts Occur

git checkout main git merge feature-branch # Output: # Auto-merging style.css # CONFLICT (content): Merge conflict in style.css # Automatic merge failed; fix conflicts and then commit the result.

Conflict Markers in File

/* style.css */ button { padding: 10px 20px; <<<<<<< HEAD background: blue; color: white; ======= background: green; color: #fff; >>>>>>> feature-branch border: none; }

Explanation:

  • <<<<<<< HEAD: Your current branch (main)
  • =======: Divider
  • >>>>>>> feature-branch: Incoming changes

Resolving Conflicts

  1. Open the conflicted file
  2. Choose which version to keep (or combine both)
  3. Remove conflict markers
  4. Add and commit
/* After resolution - choose what you want */ button { padding: 10px 20px; background: green; /* Kept feature-branch version */ color: white; border: none; }
# After fixing conflicts git add style.css git commit -m "Resolve merge conflict in button styling"

Check Conflict Status

# See conflicted files git status # Unmerged paths: # (use "git add ..." to mark resolution) # both modified: style.css # Abort merge if needed git merge --abort

🔄 Collaborative Workflow

Feature Branch Workflow

  1. Pull latest changes: git pull origin main
  2. Create feature branch: git checkout -b feature-name
  3. Work and commit: Make multiple commits
  4. Push branch: git push -u origin feature-name
  5. Create Pull Request: On GitHub
  6. Code Review: Team reviews your changes
  7. Merge: After approval, merge to main
  8. Delete branch: Clean up after merge

Best Practices

  • ✅ Use descriptive branch names: feature-user-auth, fix-login-bug
  • ✅ Keep branches short-lived
  • ✅ Commit often with clear messages
  • ✅ Pull from main regularly to avoid conflicts
  • ✅ Test before merging
  • ❌ Don't commit directly to main in team projects
  • ❌ Don't have multiple features in one branch

Part 4: Simulate Merge Conflict

# 1. Create two branches from main git checkout main git checkout -b style-update-1 # 2. 🎓 Git Branching Cheat Sheet

# View branches git branch # Local branches git branch -a # All branches git branch -r # Remote branches # Create branches git branch branch-name # Create git checkout -b branch-name # Create and switch # Switch branches git checkout branch-name # Old way git switch branch-name # New way (Git 2.23+) # Merge branches git merge branch-name # Merge into current branch git merge --no-ff branch-name # Force merge commit # Delete branches git branch -d branch-name # Safe delete (merged only) git branch -D branch-name # Force delete git push origin --delete branch-name # Delete remote # Update branch git pull origin main # Get latest from remote git fetch # Fetch without merging # Undo merge git merge --abort # Cancel conflicted merge git reset --hard HEAD~1 # Undo last merge (careful!) # Compare branches git diff main..feature # See differences git log main..feature # See commits
