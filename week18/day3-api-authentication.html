📚 What is API Authentication?

🔐 Understanding API Authentication

API Authentication is the process of verifying the identity of a user or application trying to access your API. Unlike web applications where users log in via forms and sessions, APIs typically use tokens for authentication.

Why API Authentication Matters

  • Security: Protect sensitive data from unauthorized access
  • User Identification: Know who is making each request
  • Rate Limiting: Control how often users can access resources
  • Access Control: Restrict what different users can do
  • Audit Trail: Track who did what and when

Authentication Methods

Method Description Use Case
Basic Auth Username and password in headers Simple APIs, internal tools
API Tokens Long-lived tokens for authentication Mobile apps, SPAs
OAuth 2.0 Delegated authorization protocol Third-party integrations
JWT Self-contained tokens with claims Stateless authentication

💡 Bearer Token Authentication

Bearer tokens are the most common way to authenticate API requests. The client includes the token in the Authorization header:

Authorization: Bearer YOUR_TOKEN_HERE

This tells the server "I am the bearer (holder) of this token, please authenticate me."

🚀 Laravel Sanctum Overview

What is Laravel Sanctum?

Laravel Sanctum provides a lightweight authentication system for SPAs (Single Page Applications), mobile applications, and simple token-based APIs. It's simpler than OAuth but more secure than basic authentication.

Sanctum Features

  • API Token Authentication: Issue tokens to users for API access
  • SPA Authentication: Cookie-based authentication for SPAs
  • Mobile Authentication: Token-based auth for mobile apps
  • Token Abilities: Assign permissions to specific tokens
  • Multiple Tokens: Users can have multiple tokens (web, mobile, etc.)
  • Token Expiration: Set expiration dates for tokens

⚠️ Sanctum vs Passport

Use Sanctum when: You're building a first-party SPA or mobile app that needs simple authentication.

Use Passport when: You need full OAuth 2.0 implementation for third-party API access or complex authorization scenarios.

📦 Installing Laravel Sanctum

Step 1: Install Sanctum via Composer

# Install Sanctum package
composer require laravel/sanctum

# Publish Sanctum configuration and migrations
php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"

This command installs Sanctum and publishes its configuration file to config/sanctum.php and migration files to database/migrations/

Step 2: Run Migrations

# Create the personal_access_tokens table
php artisan migrate

This creates a table to store API tokens:

// Migration: create_personal_access_tokens_table.php
Schema::create('personal_access_tokens', function (Blueprint $table) {
    $table->id();
    $table->morphs('tokenable'); // User who owns the token
    $table->string('name'); // Token name/description
    $table->string('token', 64)->unique(); // The actual token
    $table->text('abilities')->nullable(); // Token permissions
    $table->timestamp('last_used_at')->nullable();
    $table->timestamp('expires_at')->nullable();
    $table->timestamps();
});

Step 3: Configure API Middleware

Open app/Http/Kernel.php and ensure Sanctum middleware is in the api middleware group:

// app/Http/Kernel.php
'api' => [
    \Laravel\Sanctum\Http\Middleware\EnsureFrontendRequestsAreStateful::class,

Step 4: Add Sanctum Trait to User Model

// app/Models/User.php

Auth Controller Implementation

// app/Http/Controllers/Api/AuthController.php
namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

class AuthController extends Controller
{
    /**
     * Register a new user and generate token
     */
    public function register(Request $request)
    {
        $request->validate([
            'name' => 'required|string|max:255',
            'email' => 'required|email|unique:users',
            'password' => 'required|min:8|confirmed',
        ]);

        $user = User::create([
            'name' => $request->name,
            'email' => $request->email,
            'password' => Hash::make($request->password),
        ]);

        // Generate token with name
        $token = $user->createToken('mobile-app')->plainTextToken;

        return response()->json([
            'message' => 'User registered successfully',
            'user' => $user,
            'token' => $token,
        ], 201);
    }

    /**
     * Login user and generate token
     */
    public function login(Request $request)
    {
        $request->validate([
            'email' => 'required|email',
            'password' => 'required',
        ]);

        $user = User::where('email', $request->email)->first();

        if (!$user || !Hash::check($request->password, $user->password)) {
            throw ValidationException::withMessages([
                'email' => ['The provided credentials are incorrect.'],
            ]);
        }

        // Delete old tokens (optional)
        $user->tokens()->delete();

        // Create new token
        $token = $user->createToken('api-token')->plainTextToken;

        return response()->json([
            'message' => 'Login successful',
            'user' => $user,
            'token' => $token,
        ]);
    }

    /**
     * Get authenticated user
     */
    public function user(Request $request)
    {
        return response()->json([
            'user' => $request->user(),
        ]);
    }

    /**
     * Logout user (revoke token)
     */
    public function logout(Request $request)
    {
        // Revoke current token
        $request->user()->currentAccessToken()->delete();

        return response()->json([
            'message' => 'Logged out successfully',
        ]);
    }
}

Custom Middleware for Token Validation

// app/Http/Middleware/ValidateTokenAbility.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;

class ValidateTokenAbility
{
    public function handle(Request $request, Closure $next, $ability)
    {
        if (!$request->user()->tokenCan($ability)) {
            return response()->json([
                'message' => 'Unauthorized. Token lacks required ability.'
            ], 403);
        }

        return $next($request);
    }
}

// Register in Kernel.php
protected $routeMiddleware = [
    'ability' => \App\Http\Middleware\ValidateTokenAbility::class,
];

// Use in routes
Route::middleware(['auth:sanctum', 'ability:posts:create'])
    ->post('/posts', [PostController::class, 'store']);

Setting Up Postman Authentication

Method 1: Manual Header

  1. In Postman, go to the Headers tab
  2. Add key: Authorization
  3. Add value: Bearer YOUR_TOKEN_HERE

Method 2: Postman Variables

  1. Create a collection variable: auth_token
  2. After login, save token: pm.environment.set("auth_token", pm.response.json().token)
  3. Use in headers: Bearer {{auth_token}}

Method 3: Bearer Token Type

  1. Go to Authorization tab
  2. Select Type: "Bearer Token"
  3. Paste your token

Revoking Tokens

$request->user()->tokens()->where('id', $tokenId)->delete();

// Revoke all tokens for user

Token Management Endpoints

// routes/api.php
Route::middleware('auth:sanctum')->group(function () {
    // List all tokens
    Route::get('/tokens', [TokenController::class, 'index']);
    
    // Revoke specific token
    Route::delete('/tokens/{id}', [TokenController::class, 'destroy']);
    
    // Revoke all tokens
    Route::post('/tokens/revoke-all', [TokenController::class, 'revokeAll']);
});
// app/Http/Controllers/Api/TokenController.php
namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;

class TokenController extends Controller
{
    /**
     * List all tokens for authenticated user
     */
    public function index(Request $request)
    {
        $tokens = $request->user()->tokens;
        
        return response()->json([
            'tokens' => $tokens->map(function ($token) {
                return [
                    'id' => $token->id,
                    'name' => $token->name,
                    'abilities' => $token->abilities,
                    'last_used_at' => $token->last_used_at,
                    'created_at' => $token->created_at,
                ];
            }),
        ]);
    }

    /**
     * Revoke specific token
     */
    public function destroy(Request $request, $tokenId)
    {
        $token = $request->user()->tokens()->find($tokenId);
        
        if (!$token) {
            return response()->json([
                'message' => 'Token not found'
            ], 404);
        }
        
        $token->delete();
        
        return response()->json([
            'message' => 'Token revoked successfully'
        ]);
    }

    /**
     * Revoke all tokens except current
     */
    public function revokeAll(Request $request)
    {
        $currentTokenId = $request->user()->currentAccessToken()->id;
        
        $request->user()->tokens()
            ->where('id', '!=', $currentTokenId)
            ->delete();
        
        return response()->json([
            'message' => 'All other tokens revoked successfully'
        ]);
    }
}

🛡️ Security Best Practices

⚠️ Critical Security Rules

  • NEVER store plain text tokens in your database
  • ALWAYS use HTTPS in production to encrypt token transmission
  • NEVER expose tokens in URLs (use headers only)
  • ALWAYS implement rate limiting to prevent brute force attacks
  • NEVER share tokens between users or applications

1. Rate Limiting

// app/Providers/RouteServiceProvider.php
use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Support\Facades\RateLimiter;

protected function configureRateLimiting()
{
    RateLimiter::for('api', function (Request $request) {
        return Limit::perMinute(60)->by($request->user()?->id ?: $request->ip());
    });
    
    // Stricter limit for auth endpoints
    RateLimiter::for('auth', function (Request $request) {
        return Limit::perMinute(5)->by($request->ip());
    });
}

// Apply in routes
Route::middleware('throttle:auth')->group(function () {
    Route::post('/login', [AuthController::class, 'login']);
    Route::post('/register', [AuthController::class, 'register']);
});

2. Token Rotation

// Implement token rotation on sensitive actions
public function changePassword(Request $request)
{
    $request->validate([
        'current_password' => 'required',
        'new_password' => 'required|min:8|confirmed',
    ]);
    
    // Verify current password
    if (!Hash::check($request->current_password, $request->user()->password)) {
        return response()->json(['message' => 'Invalid password'], 401);
    }
    
    // Update password
    $request->user()->update([
        'password' => Hash::make($request->new_password)
    ]);
    
    // Revoke all tokens (force re-login)
    $request->user()->tokens()->delete();
    
    return response()->json([
        'message' => 'Password changed. Please login again.'
    ]);
}

3. IP Whitelisting (Optional)

// Create middleware for IP restriction
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;

class RestrictIpAddress
{
    protected $allowedIps = [
        '192.168.1.1',
        '10.0.0.1',
    ];
    
    public function handle(Request $request, Closure $next)
    {
        if (!in_array($request->ip(), $this->allowedIps)) {
            return response()->json([
                'message' => 'Access denied from this IP'
            ], 403);
        }
        
        return $next($request);
    }
}

5. Secure Token Storage (Client-Side)

Best Practices for Mobile/Web Apps

  • Never: Store tokens in plaintext files or insecure locations
  • Encrypt: Consider encrypting tokens before storing

    // Post management
    Route::post('/posts', [PostController::class, 'store']);
    Route::put('/posts/{id}', [PostController::class, 'update']);
    Route::delete('/posts/{id}', [PostController::class, 'destroy']);
});
// app/Http/Controllers/Api/PostController.php
namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\Post;
use Illuminate\Http\Request;

class PostController extends Controller
{
    public function index()
    {
        $posts = Post::with('user:id,name')->latest()->paginate(15);
        return response()->json($posts);
    }

    public function show($id)
    {
        $post = Post::with('user:id,name')->findOrFail($id);
        return response()->json($post);
    }

    public function store(Request $request)
    {
        $request->validate([
            'title' => 'required|max:255',
            'content' => 'required',
        ]);

        $post = $request->user()->posts()->create([
            'title' => $request->title,
            'content' => $request->content,
        ]);

        return response()->json($post, 201);
    }

    public function update(Request $request, $id)
    {
        $post = Post::findOrFail($id);

        // Check if user owns the post
        if ($post->user_id !== $request->user()->id) {
            return response()->json([
                'message' => 'Unauthorized'
            ], 403);
        }

        $request->validate([
            'title' => 'sometimes|required|max:255',
            'content' => 'sometimes|required',
        ]);

        $post->update($request->only(['title', 'content']));

        return response()->json($post);
    }

    public function destroy(Request $request, $id)
    {
        $post = Post::findOrFail($id);

        if ($post->user_id !== $request->user()->id) {
            return response()->json([
                'message' => 'Unauthorized'
            ], 403);
        }

        $post->delete();

        return response()->json([
            'message' => 'Post deleted successfully'
        ]);
    }
}
